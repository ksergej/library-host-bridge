### A1. MQ gateway + конфигурация

**3. Реализовать `CicsMqGatewayTemplate` по стратегии `CorrelId = MsgId` (P0)**  
- Объявить метод, например:
  - `byte[] callHost(byte[] requestPayload, String requestQueue, String replyQueue, Duration timeout)`
- Реализация:
  - Отправить сообщение в `requestQueue` через `JmsTemplate`:
    - создать `BytesMessage` или `TextMessage` и записать `requestPayload`.
  - После отправки прочитать `JMSMessageID` отправленного сообщения.
  - Сформировать JMS selector:
    - `String selector = "JMSCorrelationID = '" + messageId + "'";`
  - Вызвать `jmsTemplate.receiveSelected(replyQueue, selector)` с таймаутом.
  - Вернуть тело ответа как `byte[]`.
  - В случае таймаута/ошибки выбрасывать свои `HostTimeoutException` / `HostCommunicationException`.

**4. Вынести имена очередей и таймаут в `application.yml` (P0)**  
- В `application.yml`:
  ```yaml
  library:
    mq:
      request-queue: LIB.REQ.TEST
      reply-queue: LIB.REP.TEST
      timeout-ms: 5000
  ```
- Создать класс конфигурации пропертей, например `LibraryMqProperties`.
- Подключить эти настройки в `CicsMqGatewayTemplate` / `LibraryMqAdapter`.
- Убедиться, что имена очередей совпадают с теми, что используются в COBOL/JCL.

**5. Добавить JMS/MQ-конфигурацию (P0)**  
- В `application.yml` указать параметры для выбранного провайдера (IBM MQ / Artemis):
  - host, port, channel/queueManager (для IBM MQ) или аналогичные для Artemis.
- В `@Configuration` классе:
  - объявить `ConnectionFactory`,
  - объявить `JmsTemplate`,
  - по необходимости — `DefaultJmsListenerContainerFactory` (на будущее).
